# 测试记录

运行版本 `v2.2-names-candidate`。文档与辅助工具修订为 `release-r2`（2026-11-23）。

## 原机与离线样本

| 检查项目 | 结果 |
|---|---|
| 原机显示 | 使用者在 v2.2 姓名修复后反馈显示正常。发布前没有另开一局复测。 |
| 坐标基线 | 8184 条 PCAP 记录，7101 条坐标与 CSV 逐条一致。对照项包括包号、类别、实体字段、scale、原始坐标值、帧号、时间戳和 XYZ。 |
| 缺名样本 | 5236 个包。修复后解析到的姓名从 2 个增至 4 个，坐标从 4363 条增至 4429 条。解码到 7 个 HP 动作，应用错误数为 0，遇到 4 个未支持的 IPv4 分片。 |
| 身份关联 | 在原机后端的离线核对中，名单按运行时实体编号关联坐标，能区分本地身份和其他实体。 |

缺名样本中，一条 UDP 记录包含两条连续的 3/6 消息。旧版只读到了其中一条。修复后有两条 UDP 记录拆出四段，另重组了一条完整的传输消息。

v2.1 以前，抓包进程会随端口变化反复启停，历史记录中出现过数秒空窗。新版持续抓包，端口变化时只更新归属记录。空窗期缺少的字节无法补回，抓包仍可能丢包。

## PCAP 离线工具

`v22-validation.json` 记录的坐标基线包含 2830 条入站应用消息、2752 个场景帧、20421 个动作、7101 个位置动作，其中记录到 17 次 Zstd 解压。原始验证文件含玩家资料，保存在本地。

`release-r2` 在同一份 8184 条记录的旧 PCAP 上，用已确认的主端口分方向重新统计。按方向选取应用体偏移并去重后，共读取 3733 条应用消息，其中入站 2830 条，出站 903 条。入站 3/852 有 2752 条，出站 3/851 有 815 条，Zstd 统计为 17。研究工具第一次把出站记录按入站格式读取，修正后重新核对了结果。旧版的 2830 只统计入站，双向统计以这次重算为准。

在这份 PCAP 中，从第 3 条记录提取了带位置的 3/852 消息，逐层读取场景、第一条实体和第一条动作。指定已有输出时，工具按预期拒绝覆盖文件。`legacy_move50.py` 只检查了帮助输出和语法，作为旧版 3/50 的静态分析参考。没有使用合成流量或进行新的现场采集。

## 发布文件与研究工具

- 原机的九个运行文件可用 [SOURCE_ORIGIN.json](../SOURCE_ORIGIN.json) 中的 SHA-256 核对。`build_dist.py --check` 检查 Python 语法和运行文件的一致性，`publish_check.py` 检查发布目录和清单，加上 `--archive` 时也检查 ZIP。命令见[部署与复现](REPRODUCE.md)。
- 用已有输入检查了热更新提取和恢复脚本。提取的 `UpdateScript_500.dll`、恢复后的 metadata 和 IL2CPP 分析副本的 SHA-256 都与已知值一致。IL2CPP 恢复会读取前一步的 metadata 报告。完整代码区恢复和全新 native Dump 尚未验证。
- 三个 .NET 工程尚未用标准 SDK 实际构建，也未独立验证从头在另一台电脑或手机完成全部研究、部署和现场运行。

## 已知限制

- 当前不支持 IPv4 或 IPv6 分片重组，也无法修复缺片或乱序的传输分片。即使应用错误数为 0，离线报告仍可能列出未支持或未处理的记录。PCAP 长度和结构检查只能发现工具读得到的文件问题。
- 暂无地图配准、朝向、敌我识别、最大 HP、血量百分比或网络外实体。
- 3/2005 指的是当前观察目标，可能与原登录账号不同。HP 的其他值尚未逐项核对 IL。
- 抓包会记录全机 UDP，缓存会按时间、条数和体积淘汰旧记录。使用自己的样本复核，原始流量和日志留在本地。
