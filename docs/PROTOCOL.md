# 已确认协议摘要（固定版本）

适用：Android `1.35.20.001`、Unity `2022.3.62f3`、IL2CPP metadata v31，固定热更新程序集与原生库。**其他版本不可直接套用。**

## 传输外壳

- 经典 PCAP，UDP 载荷；只处理入站游戏端口。
- 单条应用消息头（本实现观察）：
  - byte0：头校验，`(len + flag + seq_lo + seq_hi) & 0xFF`；
  - byte1：低 4 位 kind（4/5 为数据），bit4 控制/ACK，bit5 分片后续，bit6 还有后续，bit7 Zstd；
  - byte2-3：小端序号；
  - 首段 10 字节（8 字节公共头 + 2 字节），后续分片 8 字节。
- 分片：`0x20` 表示后续片，首段需带 `0x40`；后续片必须连续；完整后合并并可选 Zstd 解压。
- 一个 UDP 记录可能含多条完整连续消息，必须按校验+序号链拆分，不能只取第一条。

## 应用消息

- `module u16 BE, command u16 BE, payload`。
- 3/852 场景帧：
  - 字段 4、5：帧号；
  - 字段 6：实体；
  - 字段 7：移除实体 ID（varint 或 packed）。
- 实体：字段 1 运行时实体号，字段 2 次编号/预制体相关编号，字段 3 类别，字段 4 动作列表。
- 动作：字段 1 类型，字段 2 scale，字段 3 值（varint 或 packed），字段 4 保留/未用。
- 动作 1（Position）：值三分量，XYZ = raw / scale（消息 scale 1000）。signed int64 补码还原。
- 动作 31（HP）：第一值 `conv.i4` 为生命值原值。**不要除以坐标 scale。**
  - 其他值字段用途需结合固定程序集对应 IL 复核；本轮未重新独立验证其语义。不得将任何额外值称为已确认最大血量。
- 身份：
  - 3/1：登录/重置，字段 2 本地 UID、字段 3 本地实体号、字段 5 名单；
  - 3/3、3/6：名单；3/6 字段 2 可 packed/unpacked 移除 ID；
  - 玩家消息：字段 1 UInt32 实体号、字段 2 UInt64 UID、字段 3 UTF-8 姓名；
  - 3/2005：当前观察目标通知，不保证原登录账号。
- 其他已取证：855 阶段变化；861 UInt32→UInt32 字典更新；858 UGC 语音录制。**均不是姓名或 HP 来源。**

## 关键否定结论

- 不存在“看到 TCP/独立 RPC 就能认定本局身份走那条通道”的证据。RPC 类确实存在，但本局身份消息已在 UDP 3/1/3/6 实际捕获。
- 不能用实体字段 2 当 UID；不能用坐标接近/唯一 Owner 动作猜自己；不能把非本地玩家默认标成敌人。
- 无法从旧 PCAP 的停启空窗中“补回”未记录的原始字节。

## 证据等级

A（固定版本 IL/汇编明确链）：
- 传输头/校验、分片拼接：`AsyncSend 0x5ab78..0x5abbc`、`udpParse 0x5bf04..0x5bf74`（固定样本 VA）。
- 身份解析：`MNKGAOHNBGO` parser `0x0601CD83`、登录 parser `0x060110F7`、名单 parser `0x0601B524/0x0601BF43`。
- 场景/实体分派与 HP：`0x0600654A`、`0x0600651A`、玩家动作分派 `0x060038F8`、HP 处理 `0x06003ACA`。

B（真实流量印证）：3/852 坐标、3/1/3/6 名单、动作 31 在用户会话中出现。

C/D（推断/未确认）：values[4] 的最大血量语义、跨版本兼容、未捕获通道的完整性。

token 与 RVA 只对该固定程序集/库有效；更新版本必须重新用 `research/` 工具取证。
