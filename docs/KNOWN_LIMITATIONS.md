# 已知限制

## 协议解析

- 只覆盖已取证的固定游戏版本；更新后 token、字段、传输头都可能变化。
- 只支持经典 PCAP，不支持 pcapng；不支持 IPv4/IPv6 分片重组。
- 传输分片要求首段已捕获、后续连续；缺片/乱序直接放弃并计数。
- 合包拆分只在“完整头 + 校验 + 连续序号链唯一”时执行；有多种拆法时记录为解码错误。
- Zstd 只接受有限输出大小；不实现其他压缩方式。
- 不解析/不保证 3/2005 之外的“自我”来源；观战身份有歧义。
- values[4] 最大血量语义未确认；不绘制百分比血条。

## 采集环境

- 需要 Root、tcpdump、ss、proot Ubuntu；不是独立 APK，不保证跨设备/跨 ROM。
- 全机 UDP 原始记录可能含其他应用流量；默认 600 秒/约 64 MiB 轮询停止，不是硬上限。
- 端口识别依赖 `ss` 能看见游戏 PID；辅助端口/子进程端口可能短暂出现，应用层只解已确认集合。
- 会话运行中的 Python 不会热加载新源码；升级后必须停止旧会话再启动。

## 页面显示

- 无地图底图、无地图配准、无朝向补偿、无插值预测、无敌我判断。
- 不显示最大血量/百分比、不显示网络外实体、不发送任何包。
- 不保证“进入场景就一定收到名单”；若服务器不下发，页面显示未观测到。
- 不保证所有玩家的姓名都能解析；v2.2 修复的是已经复现的合包丢弃与顺序分片场景。

## 抓包文件

原始 PCAP 会保存在设备上，可能带有玩家数据和其他应用的流量。在有权管理的设备和网络上采集，分享时只发布脱敏后的统计或合成样本。详见 [隐私说明](PRIVACY.md)。
