# 隐私与发布前脱敏

## 哪些文件敏感

| 文件/目录 | 内容 | 处理 |
|---|---|---|
| `capture-*.pcap` | 原始全机 UDP | **绝不提交/上传**；本机删除或加密保存 |
| `positions.jsonl` | 玩家/实体坐标轨迹 | 不提交；如公开只给聚合统计 |
| `metadata.jsonl` | 姓名、UID、身份事件 | 不提交；删除或脱敏 |
| `diagnostics.json` | 端口、协议计数、错误、PID | 可给脱敏计数；默认仍不提交 |
| `sockets.latest.txt` | 本机端口/PID | 不提交 |
| 会话目录/`current.txt` | 设备路径、会话时间 | 不提交 |
| 服务器地址/IP | PCAP/日志中 | 不提交；文档中也不要贴 |
| `restore-report.json` | 输入文件哈希、模块名 | 仅分析摘要可公开；原始二进制不公开 |
| 游戏 APK/DLL/SO/DAT/Dump | 版权与 ToS 风险 | **不随仓库分发** |

## 自动化保护

- `.gitignore` 已忽略 `*.pcap`、`*.pcapng`、`*.apk`、`*.so`、`*.dll`、`*.dat`、`*.csv`、`*.jsonl`、`日志/`、`临时/`、`input/`、`private/`、`work/`、`build/`。
- `tools/publish_check.py` 会扫描常见敏感后缀、绝对设备路径、会话目录、可能的玩家姓名/UID、以及应该被忽略却已存在的文件。
- 它是**启发式检查**，不是隐私审计的替代。发布前必须人工 `git status` 和 `git diff --cached`。

## 文档中已经做的脱敏

- 仓库不写服务器 IP、玩家姓名、UID、设备用户名。
- 用“用户会话”“固定样本”描述验证，不贴原始日志/坐标。
- `SOURCE_ORIGIN.json` 只保留运行文件哈希，不含玩家数据。

## 如果误提交

立即停止推送；不要在公开仓库“补一个删除提交”就认为安全（历史仍可访问）。先在本地移除敏感文件、评估是否已推送，再按平台支持的历史清理流程处理；必要时更换受影响账号/凭据。作者无法替你处理已公开的数据。
