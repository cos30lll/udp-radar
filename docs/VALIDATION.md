# 测试记录

下表记录运行版本 `v2.2-names-candidate` 的结果。文档和研究工具在 2026-11-23 更新到 `release-r2`。

| 样本 | 结果 |
|---|---|
| 原机反馈 | 使用者确认 v2.2 能正常显示姓名。发布前没有另开一局复测。 |
| 坐标基线 | 8184 条 PCAP 记录，7101 条坐标与 CSV 逐条一致。核对了包号、类别、实体字段、scale、原始值、帧号、时间戳及 XYZ。 |
| 缺名样本 | 5236 个包。姓名从 2 个增至 4 个，坐标从 4363 条增至 4429 条。读到 7 个 HP 动作，应用解码错误为 0，另有 4 个未支持的 IPv4 分片。 |
| 实体关联 | 离线核对了名单与坐标的关联，使用运行时实体号区分本地身份和其他实体。 |

缺名样本的一条 UDP 记录里有两条连续的 3/6 消息，旧版只读到第一条。修复后，两条 UDP 记录共拆出四段，另有一条传输消息由分片重组。v2.1 起，端口变化时直接更新端口归属，抓包进程可以一直运行。

## 离线工具

- 回放坐标基线的 PCAP 共读到 3733 条应用消息，做了 17 次 Zstd 解压。2830 条入站消息里有 2752 条 3/852，共含 20421 个场景动作。按出站传输头读取的 903 条消息里，有 815 条是 3/851。
- 从同一份 PCAP 的第 3 条记录提取了带位置的 3/852，逐层检查场景、第一条实体和第一条动作。指定已有输出文件时，工具会拒绝覆盖。`legacy_move50.py` 只检查了语法和帮助输出。
- `UpdateScript_500.dll`、恢复出的 metadata 和 IL2CPP 分析副本的 SHA-256 都与已知值一致。IL2CPP 恢复会读取前一步的 metadata 报告。

尚未验证完整代码区恢复、全新 native Dump、三个 .NET 工程的 SDK 构建，以及另一台手机上的部署和现场运行。原机文件的哈希见 [SOURCE_ORIGIN.json](../SOURCE_ORIGIN.json)，协议和页面的限制见 [已知限制](KNOWN_LIMITATIONS.md)。
